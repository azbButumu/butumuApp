# データベースのルール（どちらも任意・いま適用する必要はありません）

**現状のアプリはルールを変更しなくても動きます。** ここにあるのは、
後でデータへのアクセスを絞りたくなったときに貼り付けるためのファイルです。

| ファイル | ログイン | 招待コードの検証 |
|---|---|---|
| （適用しない＝現状） | 不要 | アプリ内のみ |
| `database.rules.login-required.json` | 必須 | アプリ内のみ |
| `database.rules.strict.json` | 必須 | サーバーでも検証 |

## 現状について

ルールを変えない場合、ログイン画面と招待パスワードは **アプリの画面上の仕切り**
であって、データ自体の保護にはなりません。Firebase の設定値はアプリのコードに
含まれているため、それを使えばログインせずにデータベースへ直接アクセスできます。

部内だけで URL を共有して使う分には実用上これで足りますが、
「部外に漏れても困らない」とは言えない状態である点は認識しておいてください。

## 1段目: ログインを必須にする

`database.rules.login-required.json` を
Firebase Console → Realtime Database → ルール に貼って公開。

- ログインしていないクライアントは一切読み書きできなくなる
- 招待コードの照合は引き続きアプリ内のみ

**適用前に、新しいコードをデプロイしておいてください。**
古い（ログイン画面の無い）バージョンを開いている人はデータが読めなくなります。

## 2段目: 招待コードもサーバーで検証する

`database.rules.strict.json` を同じ手順で公開。

- `/members/<uid>` に正しいコードを提出して登録した人だけが読み書き可
- コードの検証がサーバー側で行われるので、アプリを改変しても通らない

切り替えると、**それまでに招待パスワードを入力して登録した人だけ**が
使える状態になります。先に部員全員にログインしてもらってから適用してください。

招待コードを変える場合は `database.rules.strict.json` 内の `ebarasoroku`
（3箇所）と `shared/auth.js` の `INVITE_CODE` の両方を直します。
